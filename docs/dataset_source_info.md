- **Dataset Title**: Online Retail
- **Provider**: UCI Machine Learning Repository

- **Access Method**: Automated ingestion via `src/ingestion/fetch_dataset.py` with SSL verification, automatic unzip, and caching to local Parquet/CSV formats.

### Dataset Overview & Business Context
This transnational data set contains all the transactions occurring between **01/12/2010 and 09/12/2011** for a UK-based and registered non-store online retail company. The company primarily sells unique all-occasion gifts. Many customers of the company are wholesalers.

### Raw Data Attributes
| Attribute Name | Raw Data Type | Description | Example Values |
| :--- | :--- | :--- | :--- |
| `InvoiceNo` | Nominal / Text | 6-digit integral number uniquely assigned to each transaction. Cancellation codes start with 'C'. | `536365`, `C536379` |
| `StockCode` | Nominal / Text | 5-digit integral number uniquely assigned to each distinct product. | `85123A`, `71053` |
| `Description` | Nominal / Text | Product (item) name. | `WHITE HANGING HEART T-LIGHT HOLDER` |
| `Quantity` | Numeric / Integer | The quantities of each product (item) per transaction. Negative for cancellations. | `6`, `24`, `-1` |
| `InvoiceDate` | Timestamp | The day and time when each transaction was generated. | `2010-12-01 08:26:00` |
| `UnitPrice` | Numeric / Decimal | Unit price of product in sterling (£ / GBP). | `2.55`, `3.39` |
| `CustomerID` | Nominal / Integer | 5-digit integral number uniquely assigned to each registered customer. Null for guest checkouts. | `17850`, `13047` |
| `Country` | Nominal / Text | The name of the country where each customer resides. | `United Kingdom`, `Germany`, `France` |

## 2. Simulated Monthly Batch Extracts (Incremental Ingestion)

To satisfy the requirement for **incremental batch processing and scheduled ingestion**:
- The historical dataset spanning 13 months (December 2010 to December 2011) is partitioned into monthly batch files:
  - `data/raw/batches/orders_2010_12.csv`
  - `data/raw/batches/orders_2011_01.csv`
  - ...
  - `data/raw/batches/orders_2011_12.csv`
- A JSON batch manifest (`data/raw/batches/batch_manifest.json`) records extraction status, line count, date boundaries, and unique batch IDs.
- The incremental ingestion runner (`run_pipeline.py --mode incremental`) processes extracts sequentially, checking for duplicate batch execution and updating warehouse fact tables idempotently.

## 3. Synthetic Customer Master Enrichment

In real-world e-commerce systems, transaction feeds are enriched with CRM / customer master records. To fulfill the **Optional Customer Enrichment** requirement:
- Generated by `src/ingestion/enrich_customers.py` using fixed random seeds (`seed=42`) for 100% reproducibility.
- Attributes synthesized for all 4,372+ distinct customers plus a standardized Guest Customer ID (`0`):
  - `gender`: Female (52%), Male (45%), Non-Binary (3%)
  - `age_group`: 18-25, 26-35, 36-50, 51-65, 65+
  - `loyalty_tier`: Bronze, Silver, Gold, Platinum
  - `preferred_device`: Mobile App, Desktop Web, Mobile Web, Tablet
  - `signup_date`: Deterministically dated prior to customer's first purchase date
- Stored at `data/raw/synthetic_customer_master.csv` and loaded into the `dim_customer` table.

## 4. Instructions to Reproduce Data Acquisition

To manually or programmatically re-acquire the dataset:
```bash
# 1. Activate virtual environment
source .venv/bin/activate

# 2. Run automated ingestion script
python -m src.ingestion.fetch_dataset

# 3. Generate monthly batch extracts and synthetic customer master
python -m src.ingestion.generate_batches
python -m src.ingestion.enrich_customers
```
The script validates MD5/file size checksums, converts the raw multi-sheet Excel file into snappy parquet and CSV, and logs the execution to `data/logs/ingestion_audit_log.json`.
